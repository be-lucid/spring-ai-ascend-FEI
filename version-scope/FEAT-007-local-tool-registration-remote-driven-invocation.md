# Agent-client 组件本地工具注册与远端驱动调用特性文档

## 1. 特性定位

FEAT-2026-007 定义 `agent-client` 当前版本承载客户端本地能力接入的事实：业务应用可以通过 SDK 声明当前调用范围内可用的本地能力，服务端 Agent 只能通过受治理请求触发这些能力，客户端执行后主动提交结果。

本特性解决的问题是：客户端页面、企业终端、插件和人工确认能力需要进入智能体执行闭环，但不能被服务端当作可直接远程调用的函数或服务端工具项。客户端能力必须先由 SDK 声明并随调用形成能力视图，再由 runtime 通过受治理通道请求执行。执行结果作为外部输入经 Gateway / IngressGateway 回到服务端，runtime 校验后决定是否推进 Task。

在总体架构中，本特性位于 application / agent-client 与 agent-runtime 端侧能力请求之间。它不替代 agent-middleware 的工具服务，也不让平台消息通道直接承载客户端本地资源访问。其事实边界是客户端 SDK 本地能力目录、能力视图、权限校验、结果提交和本地执行上下文。

本特性面向以下角色：

- 业务应用开发者：向 SDK 注册页面、终端、插件或人工确认能力。
- 企业终端集成方：把本地上下文和受控能力接入智能体调用链。
- agent-client SDK 开发者：实现本地能力声明、能力视图上报、请求接收、执行调度和结果提交 facade。
- Gateway / IngressGateway 开发者：转发能力视图、端侧能力请求和结果提交，不直接访问客户端资源。
- agent-runtime 开发者：发起端侧能力请求，并在收到客户端结果后校验恢复点和推进 Task。
- 测试与验收团队：验证能力声明、权限、超时、拒绝和执行失败语义。

本特性只定义客户端本地能力的声明、请求接收、执行和结果提交闭环。服务端如何产生端侧工具调用意图由 FEAT-2026-009 / FEAT-2026-010 承接；标准调用入口由 FEAT-2026-006 承接；Gateway 路由和总线转发由 FEAT-2026-011 / FEAT-2026-012 / FEAT-013 承接；agent-middleware 工具执行和 runtime TaskStore 不属于本特性。

## 2. 当前版本能力要求

| 能力                   | 要求级别 | 事实要求                                                                                                         |
| ---------------------- | -------- | ---------------------------------------------------------------------------------------------------------------- |
| 本地能力声明           | MUST     | SDK 必须允许业务应用声明本地能力的名称、描述、权限、有效期和必要输入输出约束。注册时 SDK 校验声明完整性。        |
| 能力视图上报           | MUST     | SDK 必须能在发起任务或补充输入时上报当前调用范围内的能力视图；能力视图只表达客户端可用能力，不是服务端工具目录。 |
| 远端驱动请求接收       | MUST     | SDK 必须能从 Gateway / runtime SSE、Task 投影或等价受治理消息中识别端侧能力请求。                                |
| 本地执行状态           | MUST     | SDK 必须为每次端侧能力请求维护本地执行状态；该状态只用于客户端执行和 UI 展示。                                   |
| 本地能力执行           | MUST     | 本地能力必须返回最小必要结果，敏感内容应脱敏或通过受治理结果通道传递。                                           |
| 单次结果提交           | MUST     | 一次端侧能力请求对应一次客户端结果提交；协议层结果必须通过 Gateway / IngressGateway 主动提交。                   |
| 工具执行结果错误结构化 | MUST     | 权限拒绝、能力缺失、用户拒绝、超时、上下文过期、重复提交和执行失败必须有结构化错误。                             |
| 状态边界               | MUST     | SDK 只保存本地执行状态，不拥有服务端 Task 权威状态，也不推进 runtime Task。                                      |

## 3. 外部接口与入口要求

| 入口                | 类型         | 事实要求                                                                                             |
| ------------------- | ------------ | ---------------------------------------------------------------------------------------------------- |
| 能力视图发布 facade | SDK facade   | 将当前能力视图通过标准 A2A 请求提交到 Gateway 入口；Gateway 入口只转发能力视图，不直接调用本地能力。 |
| 能力请求回调        | SDK 回调语义 | SDK 将 runtime / Gateway 投影的端侧能力请求交给业务侧已注册 handler。                                |
| 能力结果提交 facade | SDK facade   | 主动提交执行结果或错误信息。                                                                         |

## 4. 场景与用户旅程

| 场景                                   | 前置条件                                             | 用户/系统动作                                               | 期望行为                                                                                                                                                                                                  |
| -------------------------------------- | ---------------------------------------------------- | ----------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 本地能力声明随调用生效                 | 应用已注册本地能力                                   | 应用通过 FEAT-006 标准调用提交任务，并携带当前能力视图      | Gateway 转发能力视图；runtime 只能基于当前调用范围内的能力视图请求客户端能力。Client 每次请求都需要携带最新能力视图，以便下游 runtime 处理；Gateway 在此业务功能中只做透传。                              |
| 本地工具调用                           | 应用注册后 Client 纳入管理，runtime 发起端侧能力请求 | SDK 执行本地工具调用，并返回结果给下游（Gateway & runtime） | 首次调用时，Client 携带本地能力信息给 Gateway 并转发给 runtime；runtime 决定需要端侧能力后通过 Gateway 返回请求；Client 本地执行工具，拿到结果后通过 Gateway 转发给 runtime。                             |
| 本地工具能力不可用场景                 | 插件未安装、页面关闭、上下文过期或权限不足           | SDK 收到端侧能力请求                                        | SDK 返回 capability_not_found、stale_context、permission_denied、user_rejected 或 timeout；runtime 决定降级、重试或失败。当出现本地工具调用错误时，Client 需要将失败原因返回给下游（Gateway & runtime）。 |
| 应用集成的本地工具刷新导致能力视图刷新 | 上层业务系统业务要求，触发工具侧变更                 | SDK 随下一次标准调用对下游进行工具刷新                      | 后续服务端请求只能针对当前可用工具能力；<br />工具刷新前能力不得自动跨任务调用和复用。<br />工具刷新当前不支持实时变更，本地工具更新后必须通过新的任务重新执行，不与更新阶段正在执行的任务关联。          |

## 5. 行为语义与边界

### 5.1 核心行为语义

#### 5.1.0 能力声明语义

- 客户端能力必须由业务应用显式注册，不能由模型或服务端任意创建。
- 能力视图默认只在当前调用范围内有效。
- SDK 必须保留必要版本信息，使服务端请求可与客户端能力目录对齐。

#### 5.1.1 远端驱动语义

- 服务端只能通过受治理消息请求客户端能力，不能直接访问客户端 DOM、文件系统、插件或本地端口。
- 端侧能力请求必须包含工具名称、参数和可展示说明。
- 需要用户参与的请求必须由业务侧完成授权或确认。

#### 5.1.2 本地执行与结果提交语义

- 客户端结果是外部输入，不是服务端事实，runtime 必须校验后才能决定是否推进 Task。
- 用户拒绝、权限不足、能力不可用都应作为结构化结果提交，而不是静默丢弃。
- 一次端侧能力请求在协议层只对应一次结果提交；多步本地操作不得要求服务端直接驱动客户端内部步骤。

#### 5.1.3 错误、状态与可观测结果

| 场景       | 事实要求                                      |
| ---------- | --------------------------------------------- |
| 能力未注册 | SDK 返回 capability_not_found。               |
| 权限不足   | SDK 返回 permission_denied 或 user_rejected。 |
| 页面变化   | SDK 返回 stale_context。                      |
| 执行超时   | SDK 返回 timeout 或 expired，并停止本地执行。 |
| 重复提交   | SDK 通过幂等键返回同一结果或冲突。            |
| 任务已终态 | SDK 不再提交结果，或提交后由平台拒绝。        |

### 5.2 显式边界与不承诺项

| 边界                  | 当前版本不承诺                                     |
| --------------------- | -------------------------------------------------- |
| 服务端 Task 权威状态  | SDK 不保存 TaskStore，只保存本地执行状态。         |
| 自动上传本地敏感数据  | 本地数据默认最小化、脱敏或引用传递。               |
| 绕过 Gateway 提交结果 | 结果提交必须进入受治理入口。                       |
| 跨租户能力共享        | 客户端能力默认不跨租户、用户或 session 共享。      |
| 客户端推进 Task       | SDK 不决定服务端 Task 是否恢复、完成、失败或取消。 |

## 6. 对下游设计与实现的约束

- L2 设计必须把本特性作为客户端本地能力接入事实来源，不得把客户端能力描述为服务端可直接调用的函数。
- `agent-client`、Gateway / IngressGateway、runtime 端侧工具响应和 agent-core handoff 设计必须共享能力视图、端侧能力请求、结果提交和本地执行状态等核心语义。
- 测试必须覆盖能力声明、能力视图上报、本地执行、用户拒绝、权限不足、能力不可用、重复提交、单次结果提交和 Task 终态冲突。
- 开发指南必须强调客户端结果是外部输入，需要 runtime 校验后才能回灌 Agent。
- 任何对跨租户共享能力或客户端推进 Task 状态的新增承诺，都必须先更新本特性或新增 version-scope 特性。
- 本特性术语必须保持稳定：LocalCapability、能力视图、端侧能力请求、结果提交、本地执行状态。
